# 轻屿 macOS 版

轻屿 / Qingyu 包含音乐、置物架、粘贴板、拾光与提醒清单、邮箱、通知、天气、本机 Agent 监测和 Mac 状态。

普通用户从[第一次使用轻屿](GETTING-STARTED.md)开始，按教程配置自己的账号和权限。本页保留源码运行、开发签名及交互细节；公开发行使用[发布指南](RELEASING.md)。最低构建目标为 macOS 12.0，当前实测为 macOS 15.7.3 / Apple Silicon，Intel 与其他系统版本仍需分别验收。

## 开发运行

先取得源码并进入仓库根目录，安装 Xcode Command Line Tools 与 [Rust stable](https://rustup.rs/)。这些是源码开发依赖，普通安装用户无需安装：

```sh
QINGYU_DATA_DIR="$PWD/.dev-data" cargo run --locked --bin qingyu -- --settings
```

日常开发运行 debug 版本，开发数据保存在 `.dev-data/`，后续集成继续沿用。只有用户明确要求打包时才生成分发产物。

macOS 的 Cargo runner 会给开发进程配置持久的本机签名，并准备凭据桥接程序和固定版本的保管程序。它们保存在 `~/Library/Application Support/Qingyu Development/`，不会创建正式配置目录。签名私钥仅保存在登录钥匙串中，不可导出；无需把开发证书加入系统信任。各进程校验对方的证书、应用标识和实际子进程，凭据只通过匿名管道传递，仍由系统钥匙串保存。

直接运行 `cargo build` 生成的 `target/debug/qingyu` 也会在程序入口验证当前进程和助手；新编译的程序会先调用同一签名脚本，原子替换为签名副本并重新执行，再启动邮箱或窗口。参数（含 `--settings`）、工作目录、数据目录和输入管道均保留。已经通过验证的程序直接启动，不重复签名。若本机签名身份丢失、私钥不可用或其他构建同时替换程序，启动会明确报错并退出；不会把失败当作成功或反复重启。

真正读取钥匙串的是 `qingyu-mail-vault-v1`，首次安装后保留其原始可执行文件。应用、桥接程序、编译器和 SDK 更新都不会重编译或替换它；`cargo clean` 也不影响它。这样钥匙串的代码摘要授权不会随桥接更新失效。保留整个助手目录和登录钥匙串中的签名身份。将来修改保管协议需要新版本及显式迁移，不能原地替换 v1。

保管条目按安装版和开发版分别使用 `Qingyu.Mail.Vault.v1.Installed` 与 `Qingyu.Mail.Vault.v1.Development`。旧的 `Qingyu.Mail.Installed`、`Qingyu.Mail.Development`、`Qingyu.Mail`、`Daozai.Mail` 和对应的原助手可执行文件继续保留供兼容迁移。迁移只新增条目，安装版已保存的新值优先；已有较新条目被拒绝时不会回退到旧密码。每次迁移后用新的保管进程重读验证，重复导入不会覆盖当前值。

后台启动、断线重连和自动迁移均禁止系统密码框。如果旧条目确实还需授权，用户在「设置 → 信箱」点击「测试」后，成功读取的值会复制成保管程序自己拥有的条目，再用全新进程验证，避免只获得本次进程的临时许可。桥接程序只允许使用同一证书的 `com.qingyu.macos.debug` 与 `com.qingyu.macos` 调用。接收者没有本机开发助手时，正式 release 使用标准系统钥匙串路径，不依赖作者电脑的助手。

只检查现有邮箱凭据是否能静默读取（不启动窗口、不输出地址或授权码）：

```sh
QINGYU_DATA_DIR="$PWD/.dev-data" cargo run --locked --bin qingyu -- --mail-credential-check
python3 scripts/test-macos-dev-keychain.py
python3 scripts/test-macos-dev-startup.py
python3 scripts/test-macos-credential-vault.py
```

钥匙串测试使用临时条目检查重建、直接重启、只新增的导入与双向签名验证，结束后删除测试条目。启动测试用两次不同代码的临时构建检查直接启动、参数与管道保留、失败退出和重复启动的快速路径。开发 runner 的 `QINGYU_DEV_SIGNING_IDENTITY` 可指定默认钥匙串中已有代码签名身份的 40 位 SHA-1 指纹；缺少匹配私钥时会明确报错。

保管测试覆盖两个不同桥接代码版本、独立进程重开、安装版与开发版的新旧值优先级、拒绝访问时不回退，以及未授权调用者被拒绝。准备脚本会自动迁移账号清单中的现有凭据；也可运行 `~/Library/Application\ Support/Qingyu\ Development/qingyu-mail-credentials --migrate-existing`，只输出检查数量与不可用数量，不输出地址或授权码。

启动测试也会比较两次不同代码构建的指定代码要求，并用第一次的要求验证第二次程序，确认代码变化后仍保留同一证书与应用标识。辅助功能授权归属到运行方式与签名身份；旧 ad hoc 授权迁移、安装版与开发版的区别，以及避免把 Codex 的命令行权限误当成 GUI 权限，见[通知排查](NOTIFICATIONS.md#隐私和排查)。

## 按需打包

用户明确要求打包后运行：

```sh
bash scripts/package-macos.sh
open dist/轻屿.app
```

脚本输出 `轻屿.app`、`Qingyu-v<version>-macos-<arch>.zip` 和 SHA-256 校验文件。当前实机验证为 Apple Silicon / Metal。默认沿用本机持久签名并准备凭据助手，保护开发版到安装版的邮箱访问。Developer ID 构建使用 `QINGYU_SIGNING_IDENTITY`；显式设为 `-` 可生成 ad hoc 包。两种外部分发方式均保留标准系统钥匙串路径。

默认开发签名包尚未公证，不能直接视为公开下载发行包。签名、公证、重新压缩与跨机验收步骤见[发布指南](RELEASING.md)。

安装包也支持 `轻屿.app/Contents/MacOS/qingyu --mail-credential-check`，仅输出各提供商的凭据可读状态，不启动窗口、读取邮件或输出地址与授权码。

`⌘,` 打开设置，`⌘W` 关闭窗口。菜单栏图标提供设置、登录启动和退出。把应用移到最终安装位置后，再启用登录时启动。

## 位置与交互

默认右侧约 40% 高度，收起时保留显示时间等状态的灵动岛。在“岛屿外观”中可以选择收起样式，使用灵动岛或细把手；已有设置继续保留。

悬停展开首先显示主控总览，集中查看已开启功能的当前状态与快捷操作。主控使用左侧选中的宠物，与各功能并列，保留同一页眉和模块导航；鼠标在图标上停留约 350 毫秒即可切换，也支持点击和键盘。侧边导航不会因为悬停选择而自动滚动。编辑、输入法和拖动期间保护当前页面；离开收起后再次悬停时重新显示总览。系统开启“减少动态效果”时，宠物保持静态。

“常驻内容”提供七种宠物，可自由更换左侧形象，或选择跟随某个 Agent。“Agent 绑定”和 Agent 设置的“宠物搭档”可分别修改各智能体的宠物。右侧 Agent 只绘制宠物头像：执行时轻跳转头，等待时点亮提示，空闲时轻轻浮动。减少动态效果时头像静止。状态只来自真实任务事件；左侧选择和绑定会保存到本地设置。

主控与各功能详情采用一致的展开高度，切换功能保持外框稳定。详情通过主控与模块入口导航，面板两侧不显示切页箭头。

顶部与自由悬浮时，常驻条和展开面板通过连续的流体肩线融合，连接处不留透明间隔。展开向外舒展，收起沿同一路径回拢，始终保留顶部的常驻内容；靠近屏幕底部时向上展开。连接处与两端共用填色、描边、阴影、点击和模糊轮廓。

左右停靠默认采用 292×532 点的竖向面板。在“岛屿外观”中可分别调节“面板宽度”和“面板高度”，也可恢复默认。增大后列表显示更多行，邮件阅读和音乐内容获得更多空间。尺寸随设置保存，并按当前屏幕可用空间限制。上下肩线以柔和的内凹曲线连接屏幕边缘；收起、过渡态与展开面板保持连续轮廓，系统开启“减少动态效果”时直接切换到目标状态。

收起时可直接按住灵动岛或细把手，展开后可按住顶部时间，在所选显示器的可用区域内二维拖动。屏幕中部保持圆角悬浮；靠近左右边缘时吸附，拉开后恢复横向悬浮。展开面板和独立通知自动避开菜单栏、Dock 与屏幕边界，通知不会覆盖岛体。位置在松手后保存，Esc 取消本次拖动；设置中也提供“自由”、水平／垂直位置与居中选项。旧停靠和偏移配置在首次拖动前保持原位置。

拖动时可以跨到其他已连接显示器；设置中的“显示器”也可直接选择目标。松手将目标显示器与位置一起保存，Esc 恢复起拖时的显示器、位置和停靠边。屏幕断开时暂用主屏，重连后恢复已保存的显示器偏好。不同屏幕的负坐标、缩放与 Dock 工作区统一换算，通知仍放在目标屏内。

“收起条长度”可选择自动或 80–520 点的自定值，并可恢复自动。它只改变横条的宽度或侧条的高度，不改变字体、厚度、全局大小或展开面板尺寸。过短时按真实内容保留最小长度；岛上歌词至少 300 点，侧边细把手也只增长长轴。长条用留白分配内容。

原生窗口、Retina 缩放、模糊遮罩和命中区域共用 AppKit 点坐标。透明空白区域不拦截点击。外观、字体、键盘焦点和辅助功能跟随 macOS 平台习惯。

“悬浮云”的导航使用独立的深色半透明底，避免浅色桌面和下方窗口文字淹没图标。当前选中入口带短标记，悬停和键盘焦点保持可见；宠物与封面保留原色。

## 功能

| 功能 | 行为 |
| --- | --- |
| 音乐 | QQ 音乐官方网页内登录、收藏、歌单与播放；Apple Music、Spotify 的曲目与播放控制；可用时显示封面与歌词 |
| 置物架 | 拖入文件、打开与在 Finder 显示；只保存原文件位置 |
| 粘贴板 | 独立页面与开关；文字、截图、图片和视频的复制记录，媒体缩略图、再次复制、打开、固定与删除；忽略敏感和临时标记 |
| 待办 | 任务、完成状态与到期提醒 |
| 邮箱 | IMAP、邮件摘要、全文与验证码；密码存入系统钥匙串 |
| 通知 | 汇总 QQ、微信等客户端的系统通知预览、未读变化、新邮件和待办提醒；可控制来源与预览隐私 |
| 天气 | 城市、实况、预报和日照；数据来自 Open-Meteo |
| Agent | 本机 agent 进程、项目和会话状态；可安装 Codex / Claude Code / Hermes 状态集成 |
| Mac 状态 | CPU、内存、磁盘、GPU 和网络；每 2 秒采样与最近 1 分钟趋势，可在功能编排中独立关闭 |

[通知接入与权限](NOTIFICATIONS.md) · [Agent 监测与状态集成](AGENT-MONITOR.md) · [Mac 状态与指标口径](MAC-STATS.md)。

播放器需已运行并提供曲目信息。首次控制 Apple Music / Spotify 时，macOS 请求自动化权限。真实邮箱账号连通性取决于网络、服务端和账号设置。

## QQ 音乐

在音乐页点击「我的歌单」，已有歌单会直接从本地缓存显示，点击一项即可按需加载并播放；需要同步新收藏或修改过的歌单时点击「刷新歌单」。首次使用时按需读取官方页面。只有官方页面明确要求登录时，岛内才显示「登录 QQ 音乐…」；点击后在内置官方页面使用 QQ 或微信登录。也可以在「设置 → 聆听」点击「打开我的音乐…」。登录后返回岛内刷新歌单。歌名、封面、进度与当前歌词跟随官方播放器页面。「播放器…」入口用于返回网页播放列表和播放控制。菜单栏的「QQ 音乐」菜单也提供网页入口。

日常启动只显示灵动岛，QQ 音乐在点击播放、选择歌单或登录时按需启动。岛内选歌不会自动展示完整播放器；读取完歌单后释放辅助网页，只保留播放所需的后台页面。侧边音乐页的「停止播放」或「设置 → 聆听 → 停止 QQ 音乐」会停止播放并关闭后台音乐页面，登录信息继续保留。

轻屿会记住上次播放的歌曲、歌单和已观察到的进度。停止播放或重启后，音乐页与主控显示上次内容，点击播放即可继续，无需重新选择歌单。官方播放器支持进度跳转时尝试恢复进度；播放结果以实际播放器状态为准。加载时再次点击可取消，网络失败后可重试。

主动刷新账号和歌单期间显示「正在恢复 QQ 音乐…」。页面加载缓慢或网络暂不可用时提供重试，不会因此将已有账号误报为未登录。本地只缓存经过校验的歌曲、歌单和播放进度等展示信息，账号凭据仍由系统 WebKit 保存。

播放与暂停点击后立即反馈，连续操作以最后一次目标状态为准；后台确认失败时恢复播放器真实状态并提示重试。

切歌时按 QQ 官方歌曲链接识别曲目，列表中的 MV、VIP 或影视说明不会使当前歌曲失效。岛内歌名、进度和歌词同步读取同一份实时快照；实时曲目优先于上次播放记忆，短暂的后台采样延迟不会把正在播放的歌曲替换为旧记录。

开发时也可以直接打开账号页：

```sh
QINGYU_DATA_DIR="$PWD/.dev-data" cargo run --locked --bin qingyu -- --settings --qq-music
```

`--qq-music-player` 直接打开播放器；已有新版实例运行时，这两个参数会激活对应窗口。

本版通过系统 WebKit 显示 QQ 音乐官方页面。登录由 QQ 音乐处理；轻屿不读取账号密码、Cookie 或登录令牌。歌曲可播放范围、会员权益和地区限制与 QQ 音乐网页版一致，部分曲目可能要求使用 QQ 音乐客户端。

macOS 14 及以上为每个数据目录使用独立、持久化的 WebKit 存储，关闭窗口或退出轻屿不会主动清除登录。开发时继续使用同一路径的 `.dev-data/`，即可复用登录状态；更换数据目录会使用另一份网页登录环境。QQ 音乐服务端使登录失效或用户退出账号后，仍需重新登录。macOS 12/13 的正式模式使用默认持久化存储，显式指定开发数据目录时为保证隔离只保留本次会话。

完整的原生账号和歌单接口需要在 [QQ 音乐开发者平台](https://y.qq.com/music_developer/#/docs/openid#/overview) 注册业务、通过审核并取得应用凭据。当前采用官方网页提供账号内容，未使用第三方逆向接口。

## 数据兼容

新默认目录：`~/Library/Application Support/Qingyu`。首次启动会兼容迁移原数据；迁移失败时保留原数据并记录原因。删除功能的旧账号和数据文件不再读取，也不会擅自删除。

开发验证使用 `QINGYU_DATA_DIR` 隔离目录。旧目录名和旧环境变量只用于兼容迁移。邮箱凭据保持可读取，诊断写入数据目录下的 `diagnostics/`。登录启动使用 `com.qingyu.macos.plist`。

```sh
cargo check --locked --all-targets --features record

```
