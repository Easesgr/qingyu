# 轻屿 macOS 设计记录

使用本地 `apple-design` 技能（来源：<https://github.com/dickwu/apple-design-skill>）。应用是 Rust / egui + AppKit 的桌面常驻工具；设计目标是让信息可扫读、设置可预测，品牌通过几何图标和青灰色表达。

## 改造前审查

- **High：位置不符合设备。** 岛体统一按 Windows 顶栏逻辑下移，未区分硬件摄像头与菜单栏；直接放回屏幕顶部又可能把内容藏到摄像头后。`layout.md › Visual hierarchy`：“Align elements to make them easier to scan”；本次将摄像头、可用区域和岛体内容使用同一套定位方案。
- **High：设置外观与系统脱节。** 彩色图标、重复的明暗主题开关和渲染后端设置加重了首屏。`settings.md › Best practices`：“Respect people’s systemwide settings”；macOS 跟随系统外观，自动选择 Metal，把位置和内容开关提前。
- **Critical：自绘控件缺少辅助功能语义。** 初次原生检查只显示设置窗口，未显示其中的控件。`accessibility.md › Vision`：“Describe your app’s interface and content for VoiceOver”；开启 AccessKit，为侧栏选择与开关补齐标签和选中状态，同时保留键盘焦点轮廓。

## 设计方案

- **单一任务：** “岛屿外观”页面帮助用户理解岛会出现在哪里，并立即调整。音乐、文件、待办、邮箱和天气在各自页面配置。
- **字体：** 应用界面统一使用内置资源圆体（Resource Han Rounded CN），覆盖中文、拉丁与数字，提供常规、中等、粗体三档。标题 20 pt，正文和控件 13 pt，说明 11–12 pt，预览内最小 10 pt。字体字节按进程共享，系统字体仅补足少见字符与其他文字。
- **颜色：** 通过 AppKit 获取语义颜色，跟随系统外观和强调色。下表为本机验证时解析的值，运行时不硬编码这些系统色。

| 角色 | 浅色 | 深色 | 对组背景的文字对比度 |
| --- | --- | --- | --- |
| 窗口 | `#ECECEC` | `#323232` | — |
| 分组表面 | `#FFFFFF` | `#1E1E1E` | — |
| 主要文字 | `#272727` | `#DDDDDD` | 14.94:1 / 12.27:1 |
| 次要文字 | `#646464` | `#9A9A9A` | 5.92:1 / 5.92:1 |
| 强调色 | `#007AFF` | `#007AFF` | 跟随用户系统设置，用于选择和交互 |
| 岛体 | 经典黑皮肤 | 经典黑皮肤 | 品牌常驻表面，保留其他可选皮肤 |

- **版式：** 780×620 pt 初始窗口，保留系统窗口框；180 pt 侧栏，单一滚动内容列；650×520 pt 最小窗口下可访问全部选项。开关点击区域至少 34×28 pt，普通按钮高度至少 28 pt。
- **辨识点：** 首页的显示器位置预览，和需要时展开的侧边空间。其他区域保持安静，不追加装饰性卡片或重复品牌图案。
- **动画：** 沿用可打断的展开过渡；尊重系统减少动态效果和减少透明度设置。

常规宽度：

```text
┌────────────────系统窗口框─────────────────┐
│ 轻屿             │ 岛屿外观              │
│ 岛屿外观       │ [显示器与岛体位置预览]  │
│ 页面与状态       │ 位置                    │
│ …                │ 显示器 / 停靠 / 定位    │
│                  │ 外观 / 常驻内容 / 启动  │
└───────────────────────────────────────────┘
```

紧凑宽度保持同样的导航和单列控件，说明文字换行，内容纵向滚动。用户无需横向滚动以找到开关。

## 定位规则

用户反馈顶部会遮挡常用点击区域后，默认入口调整为右侧偏上约 40% 位置。收起时保留可见的灵动岛；细把手作为可选样式，继续保留悬停意图缓冲。收起与展开都提供二维拖动入口，位置不再限制在边缘；靠近左右边缘时才吸附，保留原有顶部模式和旧设置位置。

- 智能定位：有刘海时把内容放在摄像头下沿；连接摄像头区域的黑色装饰不拦截点击。无刘海与外接屏使用距菜单栏 8 pt 的胶囊。
- 菜单栏下方：总是保留 8 pt 间距。
- 手动：保留自选形状、顶栏避让和停靠偏移。
- 多屏统一使用 AppKit 点坐标；Retina 只影响窗口内部栅格化。显示器断开、缩放、偏移、全屏和侧边停靠均重新计算可用范围。

这是针对屏幕边缘工具的设计判断；HIG 没有规定第三方“灵动岛”的形态。我们保留它的特色，同时遵循 `windows.md › Best practices`：“Avoid creating custom window UI”，设置窗口继续使用系统窗口控件。

## 检查与限制

设计质量验收包括：两个外观的文字对比度、最小窗口宽度、键盘导航、透明区域让出点击、真实窗口启动、刘海位置模拟及双显示器原生测试。VoiceOver 语义由 AccessKit 提供；完整的屏幕阅读器逐项验收仍需人工测试。设置控件保留系统窗口、原生菜单与键盘焦点。


## 当前品牌和功能

名称与代码标识统一为轻屿 / Qingyu。当前功能包括音乐、置物架、粘贴板、待办、邮箱、通知、天气、Agent 和 Mac 状态。旧 Git 关联与历史清理后初始化为独立仓库；必要开源版权声明放在 OPEN_SOURCE_NOTICES.md。

新图标与 UI 参考通过本机 AnyiOS 的默认图片生成配置实际生成，原图与提示词保存在 assets/qingyu/source。按最终功能清理后保留 46 个透明图标，统一光学尺寸并缓存；换肤时图标跟随文字颜色，避免浅色背景上消失。

设置侧栏品牌使用重新生成的柔软双层岛形标志与「轻屿」圆体艺术字，均为带真实 alpha 通道的透明 PNG。字标按原生前景色着色，浅色与深色背景共用同一笔画轮廓；图像保留可访问名称。原图、完整提示词和模型信息见 `assets/qingyu/source/brand-logo-rounded.json` 与 `brand-wordmark-rounded.json`，透明裁剪及光学尺寸处理见 `scripts/prepare-qingyu-brand.py`。品牌区只保留图形与艺术字。设置菜单采用自然的短名称，与设置章节和窗口标题共用同一映射。

设置集中保留日常调整：位置、面板尺寸、外观、功能开关、通知与隐私。侧边隐藏只对顶部生效的横向排列预览；歌词开关集中在聆听，提醒开关与声音集中在消息，避免重复设置入口。

设置文案以名称、当前状态和控件为主，不重复介绍功能或讲解内部实现。权限前提、隐私与数据操作后果保留简短说明；智能体接入细节和停止播放等补充说明在悬停时提供。

最新设计参考为 portrait-ui.png：左右两侧为窄高面板，沿边缘上下展开；音乐封面、标题、进度和播放控制纵向排列。原有顶部保持横向布局。真实控件保留交互和辅助功能语义，图片仅用于视觉素材。

定位预览使用生成的壁纸；交互跟随实时配置。设置窗口仍采用原生标题栏和圆体字体，强调色采用与品牌一致的深青色，选中白字满足小字对比度要求。

## 侧边连续过渡

左右面板采用 292×532 pt 的竖向布局，与屏幕接壤处使用上下内凹肩线。曲线从屏幕边缘平滑转入面板，消除独立卡片与屏幕之间的间隙。把手、动画中间态和展开态沿同一轮廓变化，允许中途收回；绘制、原生模糊遮罩与命中判定使用一致的形状。

这是轻屿针对侧边工具的形态设计判断。Apple HIG `motion.md › Providing feedback` 要求 “Aim for brevity and precision in feedback animations”，`motion.md › Best practices` 要求 “Make motion optional”；因此过渡保持简短，开启“减少动态效果”时直接切换形态。使用 AppKit 的标准材质承载背景模糊，并为“减少透明度”提供实色背景；曲线衔接不依赖玻璃效果。

## 常驻显示、移动与尺寸

收起样式明确分为“灵动岛”和“细把手”，默认保留可见的时间等状态。收起时直接按住岛体二维拖动，光标提示可抓取，不单独显示底部抓手；展开时拖动顶部时间并保留展开状态。左右吸附采用 40 点进入、76 点脱离的迟滞，屏幕中部保持悬浮胶囊。位置以所选屏幕放置区域的比例保存，松手后写入，Esc 取消；旧配置在首次拖动前沿用原定位。自由模式允许拖到屏幕顶边及菜单栏区域，只在岛体真正碰到硬件刘海时下移。窗口在内容占据顶栏时提高层级，移开后恢复，透明部分继续透传点击；松手后的回弹不能在顶部留下缝隙。窗口、岛体、点击轮廓、模糊和独立通知使用同一几何计划，展开靠近底部时向上容纳，通知在上下空隙中选择位置。

“收起条长度”仅控制常驻形态的长轴：横向宽度或侧边高度。自动值跟随真实内容，自定值为 80–520 点，实际长度至少容纳组件、歌词或把手的最小尺寸；文字、图标和厚度不缩放。长条增加组件间的留白，展开面板保持独立宽高。侧边展开进度有独立弹簧，长度接近面板高度时不会出现除零或反向进度。

横向展开保留原位的常驻岛，时间、音乐、天气与伙伴继续显示。419×286 pt 详情面板从岛下方揭开，表面间保留 8 pt 间距；底部空间不足时改从上方揭开，驻留岛不随面板重新居中。原生画布同时预留两块表面、阴影和通知位置，命中与模糊使用独立闭合轮廓。间隙让出桌面点击，但连接区域维持悬停，鼠标可连续移入面板。小屏幕或较大缩放先适配根缩放，保持详情逻辑尺寸和内部布局，不用重叠驻留岛来容纳面板。

顶边定位不能只验证逻辑轮廓：AppKit 默认的 `constrainFrameRect:toScreen:` 会把含透明留白的窗口从屏幕上方移回菜单栏下方。只对轻屿岛体和其模糊子窗口保留外部定位计划的 frame；设置、阅读和其他普通窗口继续调用系统原方法。原生 smoke 在两块真实屏幕上验证 0.8×、1×、1.4× 的透明画布可伸出屏幕上方，岛体可见顶边仍准确落在屏幕顶边，销毁岛体后恢复普通约束行为。

离开常驻岛和展开面板后保留 500 ms，再开始收起；重新进入任一表面或连接区域立即取消收起。NN/g 的 [Timing Guidelines for Exposing Hidden Content](https://www.nngroup.com/articles/timing-exposing-content/) 建议 “Keep displaying the exposed content until the cursor has left the triggering target area or the exposed content for longer than 0.5 seconds.” 该时长用于离开缓冲，展开意图仍沿用原有 200 ms（顶部）和 450 ms（侧边）。无后续指针事件时仍安排截止时间重绘。齿轮旁的 28 pt 图钉切换会话内“钉在这里”，选中时保持展开；取消钉住后恢复离开缓冲。Esc 可解除钉住，锁屏和系统主动隐藏清除状态，避免恢复时自动暴露内容。

侧边面板独立保存宽高。较大的面板增加列表、歌词和邮件正文的可用空间，控件和文字保留正常大小。当前屏幕无法容纳请求尺寸时，以可用空间限制实际尺寸；原生画布、点击轮廓和模糊遮罩共同采用该尺寸。

这些设置服务于用户对常驻信息和内容容量的明确需求。Apple HIG `settings.md › Best practices` 要求 “Minimize the number of settings you offer”，因此仅提供位置、收起样式、收起条长度、独立面板宽高和恢复选项；移动同时支持直接操作和设置调整。

## 消息与执行状态

通知显示在原岛下方的独立单行浮条中，保留岛体原内容、尺寸与导航。浮条进入与离开时，点击范围与模糊遮罩跟随可见形状。来源、标题与结果文字承担信息表达，动画和颜色只作辅助。

顶部和左右侧通知共用 380×44 pt 浮条，并根据屏幕可用空间收窄。对话名、状态与紧凑用时排在同一行，不重复显示来源或完成文案。完成通知优先保留本轮总用时；长对话名截断，完整内容保留在悬停说明和查看入口。查看与关闭按钮均至少 28×28 pt，绘制、点击范围与原生模糊遮罩共用浮条几何。

浮条中的图标与消息正文可以直接点击，与“查看”按钮触发相同动作；关闭按钮独立命中，只关闭消息。打开后立即移除当前浮条及该条通知记录，保留其他未处理消息；同一系统事件的迟到副本不会重新弹出，新的独立消息仍正常接收。Codex、Claude 提醒跳转到对应的外部应用／执行窗口，不切到轻屿的 Agent 页面。普通通知停留 15 秒，等待确认与中断通知停留 20 秒；鼠标悬停或消息操作具有键盘焦点时暂停倒计时。作为时长参考，Material 2 的 [Snackbar Behavior](https://m2.material.io/components/snackbars#behavior) 建议一般信息提示停留 4–10 秒；轻屿按用户阅读与点击的需要采用更长时间。

Agent 通知只由当前轮次的真实事件触发：开始、等待确认／中断、完成；不轮播执行中状态。事件按对话、轮次和类型去重，启动、锁屏恢复与监测重启先建立安静基线。完成需要明确的成功事件，总用时冻结为本轮开始至结束的时长；进程存在、退出或报错均不等同成功。提醒不进入通知历史，新消息优先于开始提示。

Agent 品牌图标叠加状态标记：开始为播放、等待为暂停、中断为警示、完成为对勾。各标记以不超过 650 ms 的一次动画进入后保持静止，悬停不重播；减少动态效果时直接显示最终标记。遵循 Apple HIG `motion.md › Providing feedback` 的简短、精确反馈原则，不以持续旋转暗示任务进度。

执行摘要、主控与 Agent 列表使用同一份真实对话名称，改名后同步更新；项目名不代替对话名。名称尚未取得时显示对话短标识与“名称待同步”，关闭通知预览时只保留短标识，以区分多个对话。查看操作始终定位该会话，完整名称同时用于悬停与辅助功能标签。

Apple HIG `notifications.md › Best practices` 要求 “Avoid sending multiple notifications for the same thing” 和 “Handle notifications gracefully when your app is in the foreground”。因此完成结果按任务轮次去重，首次历史数据只建立基线，动态状态与完成通知分开；用户展开面板操作时不自动切换页面。`live-activities.md › Best practices` 中聚焦简短、有始有终任务的原则用于此处的信息层级；轻屿仍是自绘 macOS 工具，不把侧边提示称为系统 ActivityKit 功能。

## 悬停主控

悬停展开以主控为入口，汇总已开启功能的当前状态、快捷操作和详情入口。主控作为导航中的独立一项，与各功能共用页眉、导航位置及内容区域；使用轻微聚合的动态图标，减少动态效果时保持静态。点击功能后进入详情，通过同一导航栏切换回主控；一次操作过程中继续悬停不改变当前内容，收起后重新悬停才回到总览。通知的明确查看操作和文件拖入继续进入对应目标。

主控按可用宽高组织固定网格，顶部三列、侧边两列，所有已启用卡片完整显示，不使用滚动容器。行高根据内容区域计算，避免小数缩放下逐行取整引起滚动条反复出现、消失和卡片宽度变化。摘要尊重功能开关与排列顺序，邮件、通知与粘贴板内容遵循既有隐私策略，后台进程不会被显示成正在执行任务。

主控卡片优先显示图标、数值、进度和状态，保留必要的一行曲名或短信息。重复的模块名称、说明句和长内容放到悬停提示或功能详情，避免总览成为文字列表。

主控与各模块详情使用一致的展开高度，切换时保持外框稳定。侧边沿用用户设定的高度，顶部统一容纳各模块；功能详情内容超出时在内部滚动。功能详情不再显示两侧切页箭头，通过并列的主控与模块入口切换，保留每个功能自己的入口。

统一高度也需要统一内容的可用区域。列表与邮件阅读随面板增加可见内容，音乐和天气根据剩余空间安排封面、控制、指标和预报；空数据使用完整的空状态。面板内部的滚动范围随内容区域计算，保留稳定的页眉与导航。

Apple HIG `layout.md › Visual hierarchy` 要求 “Use progressive disclosure to make layouts cleaner and easier to interact with”。因此主控提供状态和常用操作，完整阅读、编辑与配置仍在各功能详情和设置中完成。

## 统一通知

微信、QQ 等消息浮条为发送者标签和正文预览分别保留空间；联系人或群名过长时截断标签，正文仍可见。悬停保留系统提供的完整姓名与正文预览，正文中的验证码继续遮挡。

通知拥有独立页面和设置侧栏入口，汇总聊天客户端、新邮件与待办提醒。顶部和左右停靠共用同一份内存记录；列表优先显示来源、系统提供的发送者与预览，提供打开和移除操作。空状态直接引导配置来源，设置中说明真实权限与读取范围。沿用应用圆体字体、现有岛体皮肤和原生设置配色，操作区域至少 28 pt；没有新增图片或独立的视觉主题。

权限由用户在通知设置中主动申请，后台采集不会自动弹出授权。隐藏预览后清除已存正文，锁屏暂停采集；仅有未读标记时明确显示其范围。依据 Apple HIG `privacy.md › Best practices`：“Request access only to data that you actually need”，以及 `notifications.md › Best practices`：“Avoid sending multiple notifications for the same thing, even if someone hasn’t responded”。系统合并通知字段时保留原文，原通知失效时说明只能打开应用，避免用界面文案承诺系统没有提供的能力。

## QQ 音乐账号入口

音乐页的任务是快速进入自己的音乐，并随时回到播放控制。空状态增加「连接 QQ 音乐」和登录后的用途说明，侧边面板在封面上方提供两个 120×30 pt 的文字按钮；顶部面板在播放控制下方增加一行 160×28 pt 的按钮，避开时钟、歌名与歌词。设置中采用原生主题按钮，入口也可从系统菜单访问。控件保留辅助功能标签、键盘激活和焦点轮廓，沿用现有色彩与应用圆体字体。

收藏和歌单在岛内选择，当前歌词跟随官网高亮句。登录或用户主动打开完整播放器时，使用可调整大小的标准 Mac 窗口，保留后退和刷新。日常启动不创建音乐网页；选择歌单后仅保留一个后台播放页面，临时歌单读取页面完成后释放。停止播放关闭音乐网页但保留登录。这是在现有边缘面板中引入账号内容的局部设计判断。依据 `web-views.md › Best practices`：“Support forward and back navigation when appropriate”；`managing-accounts.md › Best practices`：“Explain the benefits of creating an account and how to sign up”。没有新增视觉素材或动画。

## 拾光：由 Hermes 整理的收藏库

原待办的页面编号和设置入口延续为「拾光」，保留提醒清单作为子视图。页面的任务是重新找到随手发给 Hermes 的想法、链接与行动，先呈现标题、摘要和来源，再按需展开原话、主题、标签和下一步。顶部使用分类列与阅读列，左右使用搜索、分类和纵向列表；增大侧边面板显示更多真实内容。沿用应用圆体字体和岛体皮肤，正文 13 pt，元数据 10.5–11.5 pt，交互控件 28 pt，保留键盘焦点轮廓，没有新增装饰动画。

采用 Apple HIG `search-fields.md › Scope bars and tokens`：“Default to a broader scope and let people refine it as they need”，默认展示全部内容，搜索原话、摘要、主题与标签，并提供待回顾、置顶和归档视图。依据 `lists-and-tables.md › Content`：“Keep item text succinct so row content is comfortable to read”，列表只呈现可扫读的摘要，完整内容在内部滚动详情中阅读。

Hermes 整理结果与用户原话明确分开，手动内容不显示虚构的 AI 摘要；归档可恢复、行动可重新打开。依据 `generative-ai.md › Transparency`：“Set clear expectations about what your AI-powered feature can and can’t do”，安装入口说明本机技能安装与微信网关连接的区别，无法读取的视频只保留链接和用户附言。原待办数据和提醒行为继续由原有模型处理。
