# 本机 Agent 监测

新用户先按[首次使用教程](GETTING-STARTED.md#7-接入-codexclaude-code-和-hermes)配置自己的本机 Agent。下文的 Agent 设置对应侧栏「智能体」。

在轻屿的「Agent」页查看本机正在运行的 agent。每个会话默认收成一行，显示对话名称、运行时长和状态；点击可展开或收起项目与工具详情。顶部停靠采用横向列表，左右停靠采用竖向列表，列表可独立滚动。

页面只列出正在执行或等待处理的任务。完成任务保留 **1 分钟**，随后自动消失；刷新、重命名或重复完成事件都不会延长停留时间。闲置对话、后台进程和历史任务不在任务列表中显示，任务完成提醒也不加入通知记录。

运行时长从当前一轮任务开始计时，执行工具和等待输入时不会重置，结束后保留最终用时；没有可靠起点时显示「—」。对话名称读取 agent 保存的真实标题；Codex 子 Agent 优先使用自己的名称或昵称，显示为「子 Agent · 名称 · 短标识」，缺少昵称时显示角色与短标识，避免与主对话及其他子 Agent 同名。初次查询期间显示读取提示，不从项目名或对话正文生成标题。

## 岛内执行状态与完成提醒

Codex、Claude Code、Hermes 等 Agent 的真实会话开始、等待、需要审批、中断或完成时，岛下方的独立单行通知显示具体对话名称、对应应用图标与状态动画。只按事件提示，不按时间间隔重复弹出。在“设置 → 智能体 → 岛内提醒”中可分别开启开始与中断提醒、任务完成提醒。

开始和完成通知显示 15 秒，普通等待与中断显示 20 秒，悬停或键盘聚焦时暂停计时。需要审批的通知保留到用户点击或主动关闭，也保留在本次运行的通知记录中。轻屿只提示审批请求；点击消息或“查看”打开对应 Agent 应用／窗口，在原应用里操作。

观察到当前一轮任务完成后，完成通知显示本轮总用时，任务在 Agent 页保留 1 分钟后移除。同一轮任务只提醒一次；启动时已有的历史完成记录不重放。错误、中断、进程退出和仅检测到后台进程都不会被当作成功完成。

这些提示遵循通知和 Agent 功能开关、锁屏状态及系统减少动态效果设置。开始、普通等待、中断与完成通知不加入通知历史；审批提醒在处理前保持可访问。锁屏和关闭通知会清除当前内存中的提醒，解锁后不会集中重放。

Codex 已打开的对话在暂时没有新执行事件时仍保持后台会话关联，执行任务后可继续使用真实名称。手动重命名优先显示，并定期刷新。新版 Codex 的手动名称读取数据库 `threads.name`，兼容旧版的 `title` 和会话索引。

## 状态来源

轻屿自动识别 Codex、Claude Code、Hermes、Gemini CLI、OpenCode、Cursor Agent 和 Aider 的进程。进程存在只表示程序已启动；Codex 桌面后台服务常驻时，不会因此被标记为正在执行任务。

Gemini CLI、OpenCode、Cursor Agent 和 Aider 当前主要提供进程识别，尚无与 Codex / Claude / Hermes 同等完整的任务状态与完成提醒适配。监测只针对本机，不自动连接远程电脑或云端会话。

Codex 和 Claude Code 还会从本机会话日志提取项目、工具名称和执行状态。日志读取有大小与数量限制，不把历史会话直接当成当前任务。详细的开始、等待确认、工具调用、完成和错误事件由可选状态集成提供。Hermes 的详细状态需要安装插件；仅检测到进程时会继续等待真实任务事件。

macOS 进程采集命令使用固定的日期格式，因此从 Finder 启动和从终端启动使用同一解析规则；中文或其他系统语言不会影响进程识别，应用与系统的语言设置保持原样。

## 安装详细状态集成

设置会按 Agent 分别列出是否已发现应用、集成是否安装，以及是否实际收到任务状态。只有接收到近期执行事件才显示「已收到任务状态」，后台进程存在不会被计为运行任务。

1. 先安装并正常运行自己的 Agent，打开「设置 → 智能体」，点击「安装状态集成」。
2. 查看界面中的安装结果。
3. 等当前任务结束后，新开会话或安全重启需要监测的 Codex、Claude Code 或 Hermes；安装操作不会主动打断现有任务。
4. 执行一次新任务，确认设置显示「已收到任务状态」，并检查执行中显示与完成提醒。「集成已安装」本身仅说明配置已写入。

Codex / Claude 状态集成需要本机可用的 Python 3；Hermes 插件使用 Hermes 的 Python 环境。集成仅负责上报状态，不替用户批准工具调用。已有的用户 hooks 和插件配置会保留；遇到无法安全修改的配置会显示原因。

修复会识别指向同一数据目录的路径别名，并把重复的轻屿 hooks 合并为一份。修改 Claude / Hermes 配置前会在各自配置目录的 `.qingyu-backups` 中保存私有备份。当前 Hermes 安装使用官方启动器选择 Python 与依赖环境，并保留 YAML 注释、引号和其他插件设置；旧版环境继续兼容。

Hermes 的一轮任务以 `pre_llm_call` 的真实轮次标识开始，只有明确的成功结束才上报完成；普通问题等待与需要审批分别显示，中断和错误不会计为成功。并发会话按会话标识和轮次关联，缺少可核验身份的事件会被忽略。Hermes 数据库已有结束标记的会话不会被旧插件线程的延迟心跳重新列为活动任务；新的真实轮次仍可重新打开该会话。插件卸载时通过 Hermes 官方回调停止自己的观察线程并清空内存状态。

安装操作不会重启正在运行的 gateway；新版 Hermes 可通过官方插件热加载接口立即启用观察 hooks。当前进程若还运行着早于卸载清理回调的插件版本，该旧线程只能随 gateway 正常重启退出；仅在 Hermes 状态与执行记录确认无活动或审批中的任务后再安全重启。

「修复状态集成」用于重新安装轻屿管理的条目。「移除状态集成」仅移除轻屿添加的内容，随后重新启动对应 agent 生效。轻屿启动时不会自动安装集成。

## 后台与隐私

关闭「功能编排」中的智能体会停止后台监测。可以保留已安装的集成，或在「设置 → 智能体」移除。

监测在本机处理，不连接外部状态服务。展示内容包括 agent 名称、项目路径、进程号、工具名称和状态；不会展示或保存用户提示词、模型回复或工具参数。状态集成使用轻屿的数据目录，开发运行沿用 `QINGYU_DATA_DIR`。

## 实现参考

架构参考本机 `clawd-on-desk` 项目的「进程发现 + 会话日志 + hooks/plugin 事件」方式。轻屿使用独立的 Rust 监测器和状态集成，不依赖 Electron 或该项目的运行实例。

`python3 scripts/agent-monitor/verify_hermes_runtime.py` 可通过当前 Hermes 的真实插件加载器和事件分发器做离线验证。它使用临时配置、阻断网络连接，并验证并发会话的等待、审批、恢复、成功、错误与中断，不会发送模型请求或修改实际 Hermes 配置。
